# LineOfBots Modding Kit v4 — дополнение v24.8

**Файл ядра:** `lineofgui2` (ветка `main`) · **Версия кита:** 3 · **Дата:** 15 ноября 2026
**Это дополнение к MODDING_FOR_AI.md** — описывает новый API v24.5–v24.6 и исправленные баги лоадера.
Мод проверяет совместимость: `if api.version and api.version >= "v24.6" then ... end`

---

## 1. Новый официальный API

### Промпт ИИ — БЕЗ хуков
```lua
-- Подсказка в блок MOD ACTIONS системного промпта (убирается при выгрузке сама):
api.hint("Если игрок просит передать предмет — используй [DO:give ник предмет]")

api.removeHint("текст")  -- снять свою подсказку досрочно

-- Легальное расширение способностей (снимает «You CANNOT …» для перечисленного):
api.ability("teleport", "можешь телепортироваться к игроку по [DO:tp ник]")
api.removeAbility("teleport")
```
**Правило:** хукать `makeSystemPrompt` ради добавления текста больше НЕ НУЖНО.
`api.hint` + `api.ability` закрывают 95% сценариев, ради которых моды хукали промпт.

### Чат от лица бота
```lua
api.say("не нашёл игрока Влад, попробуй точный ник")  -- pcall + журнал внутри
```

### Версия кита
```lua
api.version  -- строка "v24.6" (дублируется в api.loader.VERSION)
```

## 2. Безопасность: что теперь гарантирует лоадер

| Механизм | До v24.5 | Теперь |
|---|---|---|
| `api.hook(fn, repl)` | repl ставился как есть; ошибка мода = «бот замолчал» | repl вызывается через обёртку: конвенция `repl(оригинал, ...)` работает, при ошибке — журнал с именем мода, уведомление, **авто-снятие хука**, вызов уходит в оригинал |
| `api.patch(name, wrapper)` | ошибка wrapper падала на каждом вызове | fail-safe: журнал + прозрачный вызов оригинала |
| `api.override(name, fn)` | ошибка замены падала на каждом вызове | fail-safe: журнал + вызов оригинала |
| `api.connect(signal, fn)` | битый signal ронял загрузку мода целиком | Connect под pcall; ошибка обработчика — в журнал с именем мода |
| Событие падения конвейера | только print в консоль F9 | notify в GUI + запись в журнал модов с перечнем модов с хуками |
| Загрузка модов | одна ошибка внутри `loadAll` молча убивала поток — моды не грузились до перезахода | `loadAll` под pcall: журнал + уведомление |

**Конвенция хуков:** `api.hook(LOB_CORE.makeSystemPrompt, function(old, settings) return old(settings) .. "\nМоё правило" end)` — как в §6.8 документации. Прежде эта конвенция НЕ соответствовала реализации; с v24.5 она официальная (старая сырая `repl(...)` тоже принимается для совместимости).

**После первой же ошибки хук снимается САМ** — мод должен это переживать: проверяй результат, при повторном усилении промпта используй `api.hint`.

## 3. Исправленные баги лоадера (v24.6)

1. **Моды молча не грузились** — на инжекторах без `loadstring` (только `load`) падали `loadMetaCache/loadLib/loadOne/api.data`; теперь единая точка `LOB_MODS.loadChunk` (loadstring → load → понятная ошибка в журнал).
2. **Табы-призраки** — выгрузка мода с 2+ своими вкладками оставляла каждую вторую вкладку в сайдбаре навсегда (мутация списка во время `ipairs`); обход переписан на обратный.
3. **Родные [DO:теги] умирали** — если мод переопределял `wave`/`follow` и т.п., после выгрузки тег оставался сломан до перезахода; теперь родной обработчик сохраняется и возвращается.
4. **Утечка подписок** — `api.on` не чистился при выгрузке; каждый цикл вкл/выкл наращивал `LOB_MODS.events`; теперь подписки мода снимаются, `fire` идёт по снимку списка.
5. **Запрос вкладки до готовности GUI терялся** — теперь таб регистрируется и создаётся при ближайшей пересборке интерфейса.
6. **api.every/api.delay** с не-функцией не спамят журнал; **api.version** не дублируется.

## 4. Чеклист приёма мода (обновление)

1. Включил мод → бот ответил на два сообщения (ловит класс «немого бота»).
2. Выключил мод → в сайдбаре не осталось вкладок мода, родные теги работают.
3. Включил мод снова → подписки/хуки не задублировались (журнал чистый).
4. Мод с ошибкой в `patch/hook/connect` → в GUI всплывает уведомление с именем мода, бот продолжает работать.

## 5. Ловушка кириллицы (напоминание из отчёта моддера)

`string.lower/upper` в Luau НЕ меняют регистр кириллицы. Для ников и текста игрока:
приводите регистр через `utf8.codepoint` или транслит (Влад → Vlad), иначе сравнение молча не сработает.


## 6. Что нового в v24.7 (кит 3)

Волна багфиксов бота; API модов НЕ изменился (кроме одного атрибута, см. п. 1).

### 1. Пустая вкладка при отключении мода — исправлено
БАГ: при отключении мода его вкладка оставалась в сайдбаре, но с пустым содержимым.
Причина: `unloadOne` уничтожал фрейм вкладки (mod.instances) ДО `uiRemoveTab`, а у
уничтоженного фрейма `FindFirstChild("ModScroll")` уже давал nil — вкладка считалась
«родной», и её КНОПКА не удалялась. Теперь: вкладки убираются ДО уничтожения
instances, а вкладка мода помечается атрибутом **`ModTabOwner`** (переживает
`Destroy()`), по которому `uiRemoveTab` определяет владельца даже у мёртвого фрейма.
Для модов ничего менять не нужно; атрибут ставится автоматически в `api.ui.ensureTab`.

### 2. «Вежливое внимание» умной ходьбы
- **Чужие сообщения больше не теряются:** раньше, пока бот говорил с одним игроком,
  сообщения других молча выбрасывались (фокус-гейт). Теперь они ОТКЛАДЫВАЮТСЯ
  (до 90с) и бот отвечает на паузе в разговоре; ближнего (<=80) после паузы он сам
  находит и подходит. Прямое обращение к боту по имени по-прежнему срабатывает сразу.
- **Живой разговор не обрывается:** переключение к чужому больше не происходит, пока
  бот генерирует ответ партнёру; уход от партнёра, который ПИСАЛ в этом визите, —
  только после вежливых подначек («ты тут?» -> «почему молчишь?»), а не через 30с молчания.
- **Без «спидрана» в толпе:** вежливое переключение — максимум одно за 45с, только
  на ближнего (<=45), после минимум 10с ожидания чужой реплики и на паузе в разговоре
  (партнёр молчит >=8с). При переключении партнёру кратко говорится «секунду, вернусь»
  (кулдаун 60с). Кулдаун переключения между говорящими поднят 4с -> 8с.
- **Не «ходит туда-сюда» у собеседника:** пока разговор живой, бот не догоняет каждое
  перемещение партнёра — заново подходит только если тот отошёл дальше 18 (CHAT_LEASH),
  иначе стоит и разговаривает.
- **Окно вежливого перехода живёт весь визит:** фокус истекает через 25с тишины партнёра,
  но окно переключения продолжает работать, пока визит продолжается (раньше отложенное
  чужое сообщение ждало полного конца визита).
- **Сообщение партнёра не теряется:** если отложено сообщение САМОГО собеседника (писал,
  пока бот был занят другим) — оно отдаётся сразу при встрече с ним.
- **Жёсткий потолок визита (MAX_STAY_HARD = 420с):** игрок, стоящий ЛИЦОМ к боту молча,
  подавляет подначки взглядом — без потолка бот стоял бы рядом вечно (найдено на
  тестовом полигоне). 7 минут молчания = вежливое прощание.

## 7. Что нового в v24.7.1 (кит 3)

Оба бага найдены и подтверждены на HTML-полигоне умной ходьбы (сценарий T6
«иди сюда в пути», автотест 13/13 проверок). API модов не изменился.

### 1. «Иди сюда» больше не игнорируется, пока бот идёт по своим делам
БАГ: бот шёл по своему маршруту (блуждание/визит), человек писал «иди сюда», ИИ
честно отвечал `[DO:goto]` — но бот доигрывал свой маршрут, командное движение
выглядело проигнорированным.
Причины (две):
1. Подход умной ходьбы (`lobSmartApproach`) не знал о командном движении: он
   вызывается ВНУТРИ тика и выполняет весь подход целиком; флаг `_isGoing`
   проверялся только в начале тика. MoveTo подхода (каждые 0.1с) перебивал путь
   `[DO:goto]`.
2. `ACTION_HANDLERS.goto` не коммитил визит: после подхода умная ходьба не считала
   позвавшего целью — бот уходил по старым делам или сразу блуждать дальше.
ИСПРАВЛЕНИЕ:
- `lobSmartApproach` немедленно отменяется (`_isGoing` / `_isFollowing` /
  `_followMgrActive`) — командное движение всегда перехватывает управление;
- `[DO:goto]` при включённой умной ходьбе коммитит ПОЛНЫЙ ВИЗИТ
  (`lobSmartSetTarget`): бот дойдёт, поздоровается и останется общаться.

### 2. Гонка «пока в пути» — бот бегал за попрощавшимся
БАГ: если человек говорил «пока», пока бот ещё шёл к нему (или пока партнёр
«гулял» туда-сюда у поводка), прощание не срабатывало НИКОГДА: `socialSince`
перезаписывается при каждом повторном входе в social, и сравнение
`farewellFrom > socialSince` постоянно давало false — визит не сворачивался,
бот бесконечно ходил за попрощавшимся.
ИСПРАВЛЕНИЕ: базой сравнения стало НАЧАЛО ВИЗИТА (`targetSince`, стабилен весь
визит): `farewellFrom > min(socialSince, targetSince)`. Прощания прошлых визитов
младше нового `targetSince` и по-прежнему не срабатывают; прощание в пути —
срабатывает сразу по прибытии (0 социальных секунд, подтверждено полигоном).

### 3. Полигон умной ходьбы (Kit 3): новые возможности
- Кнопка «🧪 „иди сюда", пока бот идёт» — сценарий воспроизведения бага 1.
- `[DO:goto]` в полигоне: парсер тегов, офлайн-ответ «уже бегу к тебе», реальный
  ИИ получает инструкцию всегда отвечать тегом на просьбу подойти.
- Автотест `scripts/test_poly_t6.js` (Node, DOM-заглушки): 13 проверок — старт
  блуждания, смена курса по команде, коммит визита, прибытие и разговор, чистота
  реплик (без мусорной `]`), возврат к блужданию после прощания, гонка «пока
  в пути», отсутствие ошибок в хронике.


## 8. Что нового в v24.8 (кит 4): аудит умной ходьбы

Полная ревизия конвейера умной ходьбы (~3000 строк: константы, чат-хуки, страх/доверие,
flee, подход, блуждание, главный цикл, вежливое окно, сворачивание). Каждый баг
подтверждён кодом/тестом; автотест полигона расширен до 23 проверок (T6 + T7) — 23/23.
API модов не изменился.

### 1. «Не надо» больше не считается «уйди»
`lobIsLeaveCommand` содержал «не надо»: «не надо, останься с мной!» / «мне не надо домой»
заставляли бота УЙТИ и поставить 60с бан на просящего остаться. Слово удалено из списка.

### 2. «уйди» стирает отложенное сообщение этого игрока
Раньше отложенное (вежливое окно) сообщение прогнавшего доживало до конца avoid
(60-90с) — бот внезапно отвечал человеку, который его прогнал.

### 3. «уйди/отстань» обходит фокус-гейт
Прогон от постороннего во время разговора бота откладывался в pending как обычная
реплика: команда не выполнялась вообще. Теперь leave-команда обходит гейт,
как прямое обращение по имени.

### 4. Посторонняя угроза больше не банит партнёра на 3 минуты
`lobSmartEvadeDanger` при угрозе (третье лицо) сворачивал визит, а завершение winddown
применяло к МИРНОМУ партнёру RETURN_CD_TALK (180с), как будто он сам прекратил визит.
Теперь у winddown есть причина (`windReason="threat"`): партнёр получает мягкий
RETURN_CD (30с) и revisit не назначается.

### 5. Вежливое переключение ждёт MIN_STAY у свежего визита
Приветствие идёт через synthetic-очередь «sw:uid» и НЕ пишет botReplyAt, поэтому
для только что поприветствованного партнёра «тишина» была вечной: через ~10с бот
переключался к отложенному чужому, пока приветствие ещё не дошло. Теперь у свежего
визита (<MIN_STAY) переключение блокируется — приветствие успевает дойти.

### 6. «Передумал» отменяет уход («пока!» → «стой, шучу, побудь»)
Завершение winddown игнорировало новые реплики партнёра: бот уходил с баном 180с,
даже если человек тут же писал «побудь». Теперь любая реплика НОВЕЕ прощания
возвращает бота в разговор (социальные таймеры перештампуются, старое «пока» больше
не давит). Один раз на winddown — повторные «пока» уходят по-настоящему.
